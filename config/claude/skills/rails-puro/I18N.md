# I18N — Boas práticas de internacionalização e localização

Leia ao trabalhar com strings de UI, traduções, formatos de moeda/data, ou ao localizar para PT-BR.

## Locale default

Para produtos brasileiros, defina `pt-BR` como padrão:

```ruby
# config/application.rb
config.i18n.default_locale = :"pt-BR"
config.i18n.available_locales = [:"pt-BR", :en]
config.i18n.fallbacks = [:en]
config.time_zone = "Brasilia"
```

## Estrutura de arquivos

```
config/locales/
├── pt-BR.yml              # default
├── en.yml                 # fallback
├── activerecord.pt-BR.yml # mensagens de erro de model
└── views/
    ├── users.pt-BR.yml    # opcional: split por área
    └── posts.pt-BR.yml
```

Rails carrega automaticamente tudo em `config/locales/**/*.yml`. Configure caminhos extras se precisar:

```ruby
# config/application.rb
config.i18n.load_path += Dir[Rails.root.join("config/locales/**/*.{rb,yml}")]
```

## Lazy lookup em views

Sempre use `t(".chave")` (com ponto inicial) em views:

```erb
<%# app/views/posts/show.html.erb %>
<h1><%= t(".titulo") %></h1>
<p><%= t(".descricao") %></p>
```

Resolve para `pt-BR.posts.show.titulo` automaticamente (controller + action).

```yaml
# config/locales/pt-BR.yml
pt-BR:
  posts:
    show:
      titulo: "Detalhes do post"
      descricao: "Veja informações deste post"
```

## Lookup explícito

Quando a chave não pertence ao contexto do template atual:

```erb
<%= t("shared.navbar.logout") %>
<%= t("flash.success.created", resource: "Post") %>
```

## Interpolação

```yaml
pt-BR:
  greetings:
    hello: "Olá, %{name}!"
    welcome: "Bem-vindo de volta, %{name}. Você tem %{count} novas mensagens."
```

```erb
<%= t("greetings.hello", name: @user.name) %>
<%= t("greetings.welcome", name: @user.name, count: @messages.count) %>
```

## Pluralização

```yaml
pt-BR:
  posts:
    count:
      zero: "Nenhum post"
      one: "1 post"
      other: "%{count} posts"
```

```erb
<%= t("posts.count", count: @posts.size) %>
```

Para PT-BR, Rails usa as chaves `one` (para 1) e `other` (para qualquer outro número, incluindo 0). Use `zero:` apenas se quiser tratar 0 de forma especial.

## Mensagens de erro de model

```yaml
# config/locales/pt-BR.yml
pt-BR:
  activerecord:
    models:
      user:
        one: "usuário"
        other: "usuários"
    attributes:
      user:
        email: "E-mail"
        name: "Nome"
        role: "Papel"
    errors:
      models:
        user:
          attributes:
            email:
              taken: "já está em uso"
              invalid: "tem formato inválido"
            password:
              too_short: "é muito curto (mínimo %{count} caracteres)"
```

```ruby
User.human_attribute_name(:email)  # => "E-mail"
User.model_name.human               # => "Usuário"
User.model_name.human(count: 2)     # => "Usuários"
```

### Traduções de erros genéricos

Use [rails-i18n](https://github.com/svenfuchs/rails-i18n) para traduções base de PT-BR:

```ruby
# Gemfile
gem "rails-i18n"
```

Cobre `errors.messages.blank`, `errors.messages.too_long`, formatos de data, etc.

## Formatos de data e hora

### Definir formatos nomeados

```yaml
pt-BR:
  date:
    formats:
      default: "%d/%m/%Y"
      short: "%d/%b"
      long: "%d de %B de %Y"
    day_names: [Domingo, Segunda, Terça, Quarta, Quinta, Sexta, Sábado]
    abbr_day_names: [Dom, Seg, Ter, Qua, Qui, Sex, Sáb]
    month_names: [~, Janeiro, Fevereiro, Março, Abril, Maio, Junho, Julho, Agosto, Setembro, Outubro, Novembro, Dezembro]
    abbr_month_names: [~, Jan, Fev, Mar, Abr, Mai, Jun, Jul, Ago, Set, Out, Nov, Dez]

  time:
    formats:
      default: "%d/%m/%Y %H:%M"
      short: "%d/%m %H:%M"
      long: "%d de %B de %Y às %H:%M"
```

### Usar formatos

```erb
<%# Local helpers `l` e `t` %>
<%= l(Date.current) %>                    <%# 19/05/2026 %>
<%= l(Date.current, format: :long) %>     <%# 19 de Maio de 2026 %>
<%= l(Time.current, format: :short) %>    <%# 19/05 14:30 %>
```

## Formatos de número e moeda

```yaml
pt-BR:
  number:
    format:
      separator: ","
      delimiter: "."
      precision: 2
    currency:
      format:
        unit: "R$"
        format: "%u %n"            # R$ 1.234,56
        separator: ","
        delimiter: "."
        precision: 2
    percentage:
      format:
        delimiter: "."
        format: "%n%"
```

```erb
<%= number_to_currency(1234.56) %>          <%# R$ 1.234,56 %>
<%= number_with_delimiter(1234567) %>       <%# 1.234.567 %>
<%= number_with_precision(3.14159, precision: 2) %>  <%# 3,14 %>
<%= number_to_percentage(50.5) %>           <%# 50,500% %>
```

Para money/cents, prefira armazenar em **cents** (`amount_cents :integer`) e formatar:

```ruby
# helper
def format_money(cents)
  number_to_currency(cents / 100.0)
end
```

## Trocar locale em runtime

### Por usuário logado

```ruby
class ApplicationController < ActionController::Base
  before_action :set_locale

  private

  def set_locale
    I18n.locale = current_user&.locale || I18n.default_locale
  end
end
```

### Por parâmetro / sessão / cookie

```ruby
def set_locale
  I18n.locale = params[:locale] ||
                session[:locale] ||
                http_accept_language ||
                I18n.default_locale
  session[:locale] = I18n.locale
end

private

def http_accept_language
  request.headers["Accept-Language"]
         &.scan(/[a-z\-]+/i)
         &.find { |l| I18n.available_locales.map(&:to_s).include?(l) }
end
```

### URL com locale

```ruby
# config/routes.rb
scope "(:locale)", locale: /pt-BR|en/ do
  resources :posts
end

class ApplicationController < ActionController::Base
  before_action :set_locale

  def default_url_options
    { locale: I18n.locale == I18n.default_locale ? nil : I18n.locale }
  end

  private

  def set_locale
    I18n.locale = params[:locale] || I18n.default_locale
  end
end
```

## Não use string literal PT-BR no código

```erb
<%# Ruim — string crua %>
<h1>Detalhes do post</h1>
<button>Salvar</button>
<%= flash[:notice] = "Post criado com sucesso" %>
```

```erb
<%# Bom — via i18n %>
<h1><%= t(".titulo") %></h1>
<button><%= t("buttons.save") %></button>
```

```yaml
pt-BR:
  posts:
    show:
      titulo: "Detalhes do post"
  buttons:
    save: "Salvar"
    cancel: "Cancelar"
    delete: "Excluir"
  flash:
    posts:
      created: "Post criado com sucesso"
```

## Não condicione lógica por locale

```ruby
# Ruim — código de domínio com if locale
def greeting
  if I18n.locale == :"pt-BR"
    "Olá"
  else
    "Hello"
  end
end
```

```ruby
# Bom — i18n keys
def greeting
  I18n.t("greetings.hello")
end
```

## Em models

```ruby
# Validação com mensagem traduzida
class User < ApplicationRecord
  validates :email, presence: true   # mensagem vem de errors.attributes.email.blank
end

# Mensagem customizada por validação
validates :email, format: { with: URI::MailTo::EMAIL_REGEXP, message: :invalid_format }
```

```yaml
pt-BR:
  activerecord:
    errors:
      models:
        user:
          attributes:
            email:
              invalid_format: "deve ser um endereço válido"
```

## Em mailers

```ruby
class UserMailer < ApplicationMailer
  def welcome(user)
    @user = user
    I18n.with_locale(user.locale || :"pt-BR") do
      mail(to: user.email, subject: t("mailers.user.welcome.subject", name: user.name))
    end
  end
end
```

```yaml
pt-BR:
  mailers:
    user:
      welcome:
        subject: "Bem-vindo, %{name}!"
```

## Em jobs

```ruby
class WelcomeEmailJob < ApplicationJob
  def perform(user_id)
    user = User.find(user_id)
    I18n.with_locale(user.locale || :"pt-BR") do
      UserMailer.welcome(user).deliver_now
    end
  end
end
```

Jobs rodam em workers separados — sempre defina locale explicitamente, não confie no estado global.

## Enums localizados

```ruby
class Post < ApplicationRecord
  enum status: { draft: 0, published: 1, archived: 2 }

  def human_status
    I18n.t("activerecord.attributes.post.statuses.#{status}")
  end
end
```

```yaml
pt-BR:
  activerecord:
    attributes:
      post:
        statuses:
          draft: "Rascunho"
          published: "Publicado"
          archived: "Arquivado"
```

```erb
<%= @post.human_status %>   <%# "Publicado" %>
```

## Detectar chaves faltando

```ruby
# config/environments/development.rb
config.i18n.raise_on_missing_translations = true

# config/environments/test.rb
config.i18n.raise_on_missing_translations = true
```

Em produção, chaves faltando retornam `translation missing: pt-BR.foo.bar`.

Ferramentas úteis:
- `i18n-tasks` — encontra chaves não usadas, faltando, ou duplicadas
- `bin/rails t i18n` — verifica em CI

```sh
bundle exec i18n-tasks health
bundle exec i18n-tasks missing
bundle exec i18n-tasks unused
```

## Anti-padrões

| Padrão                                        | Substituir por                                  |
|-----------------------------------------------|-------------------------------------------------|
| String literal PT-BR em view                  | `t(".chave")` + YAML                             |
| `if locale == :pt` no código                  | Chave i18n específica                            |
| Data formatada manualmente (`strftime`)       | `l(date, format: :long)` + formato em YAML       |
| Moeda formatada com `.to_s`                   | `number_to_currency(value)` + config            |
| Chaves duplicadas em vários YAMLs             | Organize por área (`views/`, `models/`, `shared/`) |
| Locale alterado globalmente em jobs           | `I18n.with_locale(...) do ... end`               |
| Mensagens de erro de model em CTRL            | Use `model.errors.full_messages` + YAML          |

## Checklist antes de commitar

- [ ] Sem strings literais (PT-BR ou EN) em views/controllers
- [ ] Lazy lookup (`t(".chave")`) em views
- [ ] Chaves organizadas hierarquicamente por área
- [ ] Formatos de data/hora definidos em YAML, usados via `l(...)`
- [ ] Moeda formatada com `number_to_currency`
- [ ] Pluralização com `count:` + chaves `one`/`other`
- [ ] Mailers e jobs usam `I18n.with_locale` explícito
- [ ] `i18n-tasks health` sem warnings (se a gem está no projeto)
